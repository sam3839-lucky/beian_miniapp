# 备案价数据库全量同步方案

## 问题

当前 `property.db` 的 `housing_units` 表是靠多次碎片化爬取拼出来的。每个盘的爬取时间不同（2025-06 到 2026-05），数据覆盖不全、部分盘数据缺失（如总章翡翠公馆仅 51 条，政府 API 中完全搜不到其楼栋名）。

## 目标

一次性从政府 API 下载全部 38.6 万条在售房源，完整重建 `housing_units` 表，后续每日增量更新。

## 方案

### 方案 A：单次全量 + 每日增量（推荐）

**全量同步（一次性）**

1. 调用 `getYsfXsPublicity`，pageSize=200（实测可行），共 ~1935 页
2. 逐页拉取，每条记录包含：`bldgNameNo`、`unitNo`、`builtInArea`、`askpriceeachB`、`askpricetotalB`、`houseUsage`、`status`、`ownerName`、`parcelNo`、`checkDate`
3. SQLite 批量写入（每 5000 条一个事务），清空旧数据后全量替换
4. 同步 `presale_permits` 表：调用 `getYsfYsPublicity`（~4400 条预售证）

**项目匹配**

API 返回数据**没有 `project_name` 字段**，需要三级匹配：
1. **楼栋名前缀匹配**：大部分盘的 bldgNameNo 含项目名（如"未来之光家园20栋" → "未来之光家园"）。对每个 bldgNameNo 前缀，与 presale_permits 的项目名做最长前缀匹配
2. **开发商匹配**：ownerName 匹配 presale_permits.name
3. **宗地号匹配**：parcelNo 匹配 presale_permits 的宗地号（需额外 API 获取）

**增量更新（每日 Cron）**

1. 只拉 `checkDate` = 当天的记录
2. 对比 `housing_units`，新增/更新/标记已删除
3. 用 `date_listed` 记录入库时间

**优点**：数据完整、可追溯、后续维护成本低
**缺点**：首次全量约需 30-40 分钟（1935 页 × ~1s）
**风险**：
- 政府 API 的 SSL 问题：本地 Mac curl 可通，服务器 Ubuntu 报 `UNSAFE_LEGACY_RENEGOTIATION_DISABLED`。解决：全量同步在本地 Mac 执行，生成完整 SQLite 后上传服务器
- API 限流：每页间隔 0.5s 防止被封
- 项目匹配准确率：前缀匹配可能误匹配（如"万科城四期M区49号楼"的 bldgNameNo 不含项目名前缀）

### 方案 B：仅增量 + 持续积累

不重建，保持现有数据，只每天爬当天更新的记录追加。

**优点**：简单、对现有数据零风险
**缺点**：已有数据永远不完整，总章翡翠公馆这种缺失永远补不上

### 方案 C：从其他数据源补充

换贝壳/链家/房天下等第三方平台爬取。

**优点**：可能有更全的项目-楼栋映射
**缺点**：第三方数据不权威，反爬严重，法律风险

---

## 推荐方案

**方案 A**：全量 + 增量。一劳永逸。

### 实施步骤

| 步骤 | 内容 | 耗时 |
|------|------|------|
| 1 | 本地 Mac 全量爬取 housing_units | ~35 min |
| 2 | 全量爬取 presale_permits | ~1 min |
| 3 | 项目匹配（前缀+开发商+宗地） | ~2 min |
| 4 | 生成新 property.db | ~1 min |
| 5 | 上传服务器，替换旧 DB | ~1 min |
| 6 | 重启 Flask 服务验证 | ~1 min |
| 7 | 部署每日增量 Cron | ~10 min |

### 脚本设计

```
sync_full/
├── sync_units.py        # 全量爬取房源
├── sync_permits.py      # 全量爬取预售证
├── match_projects.py    # 房源→项目匹配
├── rebuild_db.py        # 重建数据库
└── sync_daily.py        # 每日增量（Cron）
```

### 数据库变更

`housing_units` 新增字段：
- `source` TEXT DEFAULT 'fdc_api'  -- 数据来源
- `sync_batch` TEXT  -- 同步批次号

---

## 假设与待确认

1. 政府 API 的 pageSize=200 稳定可用（已验证）
2. API 不会中途变更或限流封 IP
3. 项目匹配准确率 > 95%（主力靠楼栋名前缀）
4. 本地 Mac 可稳定运行 ~35 分钟不断网
